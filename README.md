# Study Library

A local website + scraper for collecting Class 11 & 12 study material —
**concepts** and **practice questions** — across Math, Physics, Chemistry,
Biology and English, and browsing it from a simple local site.

- **Website**: Flask app, browse by Subject → Class (11/12) → Topic, plus
  full-text search. Runs at `http://127.0.0.1:5000`.
- **Database**: SQLite file at `data/app.db` — no server to install.
- **Scraper**: a small, extensible pipeline that fetches content and stores
  it with full provenance (source name, URL, license) on every item.

## Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt

python seed.py           # adds ~20 hand-written sample items so the site isn't empty
python app.py             # starts the site at http://127.0.0.1:5000
```

Then, to pull in real content:

```bash
python -m scraper.run_scraper                # scrape everything in sources.json
python -m scraper.run_scraper --dry-run       # see what would run, without touching the network
```

Re-run `python app.py` (or just refresh the page — SQLite is read live).

## Project structure

```
app.py                  Flask app: routes for browsing + search
models.py                SQLAlchemy models: Subject, Topic, ContentItem
config.py                 subjects/classes list, DB path
seed.py                    original sample content (not scraped)
slugify_util.py             tiny URL-slug helper

scraper/
  base_scraper.py         shared HTTP fetching: robots.txt checks, rate
                           limiting, on-disk response caching
  wikipedia_scraper.py    "concept" scraper via the Wikipedia API (JSON,
                           CC BY-SA 4.0, no CSS selectors to maintain)
  generic_scraper.py      configurable CSS-selector scraper for any other
                           site — used mainly for practice questions
  registry.py               maps a job's "source" field to its scraper function
  build_sources.py         regenerates sources.json from the curated topic list
  sources.json               the actual list of scrape jobs run_scraper.py reads
  run_scraper.py            CLI entry point

templates/, static/       Jinja templates + CSS for the site
tests/test_scraper.py     unit tests for the parsing logic (offline, uses fixtures)
```

## How content is organized

Every piece of content is a `ContentItem` under a `Topic` (which belongs to
a `Subject` + class level 11 or 12):

- `type = "concept"` — an explanation of an idea.
- `type = "practice_question"` — a question, with optional multiple-choice
  `options` and an `answer`.

Every item keeps `source_name`, `source_url`, and `license`, shown on the
page, so you always know where content came from.

## The scraper

### Concepts, via Wikipedia

`scraper/sources.json` (generated by `scraper/build_sources.py`) maps ~100
Class 11/12 syllabus topics to Wikipedia articles. It uses Wikipedia's
official JSON API (not HTML scraping), so it doesn't depend on fragile CSS
selectors. Wikipedia text is CC BY-SA 4.0 — free to reuse with attribution,
which every scraped item carries automatically.

To change which topics are covered, edit `TOPICS` in `scraper/build_sources.py`
and re-run `python -m scraper.build_sources`.

### Practice questions, via `generic_html`

Wikipedia doesn't have curriculum practice questions, so `generic_scraper.py`
gives you a **configurable, CSS-selector-driven** scraper: add a job to
`sources.json` like:

```json
{
  "subject": "Physics",
  "class_level": 11,
  "topic": "Laws of Motion",
  "type": "practice_question",
  "source": "generic_html",
  "url": "https://example.com/class-11-physics/laws-of-motion",
  "source_name": "Example Site",
  "license": "Check the site's terms before reuse",
  "selectors": {
    "item": "div.question",
    "title": ".question-text",
    "options": ".options li",
    "answer": ".answer"
  }
}
```

`sources.json` ships with one such job as a **disabled template**
(`"_disabled": true`) — copy it, point it at a real page, fill in the
selectors for that page's actual HTML (inspect the page in your browser's
dev tools), and remove `_disabled`.

**You are responsible for checking that you're allowed to scrape and store
content from whatever site you configure.** `base_scraper.py` already:

- refuses to fetch any URL robots.txt disallows for our user agent,
- rate-limits requests per host (1.5s default delay),
- caches responses on disk so re-running after a bug fix doesn't
  re-download everything.

Prefer open/free sources (open textbooks like OpenStax/NCERT, Wikipedia/
Wikibooks, question banks explicitly marked reusable) over scraping
copyrighted material from commercial coaching sites.

### CLI options

```bash
python -m scraper.run_scraper --subject Physics --class-level 11
python -m scraper.run_scraper --type concept
python -m scraper.run_scraper --topic "Laws of Motion"
python -m scraper.run_scraper --no-cache     # bypass the disk cache
python -m scraper.run_scraper --dry-run       # list matching jobs only
```

Re-running is safe: items are matched on `(topic, type, title)`, so already-scraped
content is skipped rather than duplicated.

### Adding a whole new site-specific scraper

If a site's structure needs real logic beyond CSS selectors, add a
`scrape_xxx(job) -> list[ScrapedItem]` function in a new module (see
`wikipedia_scraper.py` for the shape) and register it in `scraper/registry.py`.

## Tests

```bash
python -m unittest discover -s tests -v
```

These run entirely offline against saved fixtures in `scraper/fixtures/` —
no live network needed, so they work the same in CI/sandboxes as on your
machine.

## Notes

- This was built and tested in a network-restricted sandbox where outbound
  requests to most external hosts (including Wikipedia) are blocked by
  policy; `base_scraper`'s robots.txt check fails safe (treats a blocked
  robots.txt fetch as "disallow everything"), so scraping will correctly
  no-op there. On your own machine with normal internet access, this isn't
  an issue.
- The Flask dev server (`python app.py`) is fine for local/personal use.
  Don't expose it to the internet as-is.
